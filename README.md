# FloodGuard Firmware

เฟิร์มแวร์ระบบตรวจวัดระดับน้ำและเฝ้าระวังอุทกภัย FloodGuard ออกแบบสถาปัตยกรรมฮาร์ดแวร์แบบสองระดับ (Two-Tier Master-Subnode Architecture) เพื่อการทำงานภาคสนามที่มีความเสถียรสูง โดยแยกส่วนอ่านเซนเซอร์ออกจากส่วนส่งสัญญาณวิทยุ ทั้งสองส่วนเชื่อมต่อสื่อสารกันด้วยสายสัญญาณมาตรฐานอุตสาหกรรม RS485 และส่งข้อมูลทางไกลขึ้นสู่ระบบคลาวด์ด้วยเครือข่ายไร้สาย LoRaWAN ผ่านการยืนยันตัวตนแบบ OTAA

---

## System Overview

ระบบทำงานร่วมกันระหว่างสองโหนดหลัก โดยมีรายละเอียดการทำงานและหน้าที่ของแต่ละส่วนดังนี้

```text
┌─────────────────────────────┐           ┌─────────────────────────────────────────┐
│        sensor-subnode       │ ──RS485──►│               master-node               │ ──LoRaWAN──► Cloud / TTN
│         (ESP32-C3)          │           │        (Heltec WiFi LoRa 32 V3)         │
└─────────────────────────────┘           └─────────────────────────────────────────┘
  - อ่านระยะ Ultrasonic A01NYUB              - ส่งข้อมูลระยะไกล LoRaWAN OTAA (AS923)
  - วัดมุมเอียง GY-25 (Tilt Status)          - ซิงค์เวลาสากล Unix Epoch จาก GPS
  - ส่งข้อมูล Packet ผ่าน RS485              - สำรองข้อมูลลง Flash (LittleFS Backlog)
                                            - วัดอุณหภูมิและความชื้นกล่องด้วย SHT30
                                            - ตรวจวัดแรงดันแบตเตอรี่พร้อมวงจร Filter
                                            - ควบคุมไฟเลี้ยงภายนอกด้วย Relay Pin 26
                                            - หน้าจอ OLED แสดงสถานะและระดับน้ำ
```

### 1. โหนดลูก (sensor-subnode - ESP32-C3)

ทำหน้าที่เป็นหน่วยเก็บรวบรวมข้อมูลเซนเซอร์ภาคสนาม (Sensor Acquisition Unit) ติดตั้งใกล้ผิวน้ำ

- การวัดระดับน้ำ (Ultrasonic A01NYUB)
  ตรวจวัดระยะห่างผิวน้ำด้วยคลื่นเสียงความถี่สูงผ่านพอร์ต UART1 พร้อมระบบตรวจสอบความถูกต้อง Checksum หากค่าระยะใกล้เกินขีดจำกัดต่ำกว่า 280 มม. หรือเกิดข้อผิดพลาดจะส่งค่า fallback เป็น 0.0

- การตรวจวัดความเอียง (GY-25 Inclinometer)
  อ่านค่ามุมเอียงแกน X และแกน Y เพื่อคำนวณเวกเตอร์ความเอียงรวม (Total Tilt) พร้อมประเมินสถานะของเสาหรือทุ่นลอยน้ำออกเป็นสามระดับ ได้แก่ OK (เอียงไม่เกิน 5 องศา) WARN (เอียง 5 ถึง 10 องศา) และ TILT (เอียงเกิน 10 องศา)

- การสื่อสารผ่าน RS485 (Industrial Serial Protocol)
  ทำงานในโหมด Slave รอรับคำสั่งร้องขอข้อมูล (REQ) จากโหนดแม่ เมื่อได้รับคำสั่งจะอ่านค่าเซนเซอร์ทันทีและประกอบเป็นชุดข้อมูล Packet ส่งกลับไปยังโหนดแม่พร้อมรอรับสัญญาณยืนยัน (ACK)

### 2. โหนดแม่ (master-node - Heltec WiFi LoRa 32 V3)

ทำหน้าที่เป็นหน่วยประมวลผลหลักและศูนย์กลางการสื่อสาร (Gateway Controller Unit) ติดตั้งในจุดที่รับสัญญาณวิทยุได้ดี

- การสื่อสารระยะไกล LoRaWAN OTAA
  รองรับย่านความถี่ AS923 ส่งข้อมูลแบบยืนยันการรับส่ง (Confirmed Uplink) โดยล็อกอัตราการส่งข้อมูลไว้ที่ DataRate 2 (SF10) เพื่อความเสถียรในการเปิดหน้าต่างรับสัญญาณ พร้อมระบบ Retry ส่งซ้ำอัตโนมัติสูงสุด 2 ครั้งเมื่อไม่ได้รับ ACK จากเกตเวย์

- ระบบเวลาพิกัดและประทับเวลาสากล (GPS Unix Epoch Timestamping)
  ดึงพิกัดตำแหน่ง ละติจูด ลองจิจูด และประทับเวลามาตรฐาน Unix Epoch จากข้อมูล NMEA RMC ของโมดูล GPS ลงใน Payload ไบต์ที่ 22 ถึง 25 ช่วยให้ข้อมูลที่ส่งขึ้นคลาวด์มีเวลาที่ถูกต้องแม้ระบบจะออฟไลน์ไปนาน

- ระบบจัดเก็บข้อมูลสำรองลงแฟลช (LittleFS Offline Backlog)
  ในกรณีที่ระบบยังเชื่อมต่อเกตเวย์ไม่ได้ หรือเกตเวย์ออฟไลน์ ระบบจะบันทึกชุดข้อมูลขนาด 26 ไบต์ลงหน่วยความจำ Flash ในตัวชิปโดยอัตโนมัติ เมื่อระบบสามารถเชื่อมต่อ LoRaWAN สำเร็จ โหนดแม่จะทยอยดึงข้อมูลย้อนหลังจาก Flash ส่งขึ้นคลาวด์จนครบถ้วน

- การตรวจวัดสภาพแวดล้อมและพลังงาน (Diagnostics & Energy)
  ตรวจวัดอุณหภูมิและความชื้นภายในกล่องบรรจุอุปกรณ์ด้วยเซนเซอร์ SHT30 ผ่านบัส I2C พร้อมวงจรวัดแรงดันไฟฟ้าและคำนวณเปอร์เซ็นต์คงเหลือของแบตเตอรี่ผ่าน ADC ขา 2 ร่วมกับอัลกอริทึมกรองสัญญาณ Median และ Exponential Moving Average

- การจัดการพลังงานและหน้าจอแสดงผล (Power Management & OLED)
  ควบคุมการจ่ายไฟเลี้ยงวงจรเซนเซอร์ภายนอกผ่านสวิตช์รีเลย์ขา 26 โดยจะตัดการจ่ายไฟเมื่อเข้าสู่โหมดพักการทำงาน (Sleep Phase) เพื่อประหยัดพลังงานแบตเตอรี่ และหน้าจอ OLED จะดับอัตโนมัติเมื่อครบเวลาที่กำหนด โดยผู้ใช้งานสามารถกดปุ่ม PRG เพื่อปลุกหน้าจอขึ้นมาดูข้อมูลชั่วคราวได้

## Setup & Build

1. คัดลอกไฟล์คอนฟิกคีย์ก่อนเริ่ม build

```bash
cp master-node/include/credentials.h.example master-node/include/credentials.h
```

2. คำสั่ง build และ flash ผ่าน PlatformIO

```bash
pio run -d sensor-subnode -t upload
pio run -d master-node -t upload
```
